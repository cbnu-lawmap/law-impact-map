# 건축물대장 표제부 수집과 브이월드 값 비교

`collect/collect_register.py` 가 공공데이터포털 건축HUB 건축물대장정보 서비스(`BldRgstHubService/getBrTitleInfo`)에서 사창동 건물의 표제부를 받아 `data/bldg_register_사창동.csv` 로 저장한다. 수집은 GitHub Actions(`.github/workflows/collect-register.yml`)에서 Secret `DATA_GO_KR_KEY` 로 한 번 했다 (2026-11-23).

## 수집

- 필지마다 부르지 않고 법정동 단위(`sigunguCd` + `bjdongCd`)로 100줄씩 쪽을 넘겨 받았다. 사창동 건물 pnu 앞 10자리에 법정동이 4개 있다 (`4311210200` 2,351동, `4311311500` 47동, `4311311400` 40동, `4311210100` 10동).
- 4개 법정동 전체 16,814줄 중 사창동 건물 pnu 에 있는 필지 줄만 남겼다: **2,706줄, 필지 1,935개 / 2,063개 (93.8%)**. 지도 건물 2,448동 중 2,282동(93.2%)이 표제부가 있는 필지 위에 있다.
- GitHub 러너(해외 IP)에서도 응답이 왔다. 읽기 시간 초과가 법정동마다 1~2번 있었지만 다시 시도해서 모두 받았다.
- PNU 만들기: 시군구 5 + 법정동 5 + 대지구분 1 + 번 4 + 지 4. 표제부 `platGbCd` 는 0=대지, 1=산 이고 PNU 대지구분은 1=일반, 2=산 이라 `platGbCd + 1`. (`4311210200` + `0` → `1` + `0156` + `0005` = `4311210200101560005`, bldginfo 와 같은 형식)
- 남긴 열: `pnu, mgm_bldrgst_pk, main_purps_cd, main_purps_nm, totalarea, useapr_day, grnd_flr, hhld_cnt`. 건물명(`bldNm`)·동명(`dongNm`)처럼 이름이 섞일 수 있는 칸은 넣지 않았다 (표제부에는 소유자 칸이 없다).

| 건물 1동 · 표제부 여러 줄 (부속건물 줄 등) | 544 | 544 |

## 브이월드 값과 다른 것 (맞춘 1,163동)

연면적은 ±1% 안이면 같다고 보았다. 사용승인일은 8자리가 같아야 같다.

| 속성 | 둘 다 있음 | 다름 | 다름 비율 | 브이월드만 빈 칸 (대장이 채움) | 대장만 빈 칸 | 둘 다 빈 칸 |
|---|---|---|---|---|---|---|
| 주용도 (`usability` ↔ `mainPurpsCd`) | 1,152 | 15 | 1.3% | 11 | 0 | 0 |
| 연면적 (`totalarea` ↔ `totArea`) | 1,151 | 30 (±1% 밖) | 2.6% | 11 | 0 | 1 |
| 지상층수 (`grnd_flr` ↔ `grndFlrCnt`) | 1,152 | 15 | 1.3% | 11 | 0 | 0 |
| 사용승인일 (`useapr_day` ↔ `useAprDay`) | 1,141 | 18 | 1.6% | 11 | 10 | 1 |

- 연면적이 ±1% 안이지만 정확히 같지는 않은 건물이 9동 더 있다 (다름 30 + 9 = 39동은 대장 값으로 바뀜). ±1% 밖 30동 중 14동은 ±10% 안이다.
- 사용승인일이 다른 18동 중 3동은 같은 해(일자만 다름, 예 `19961201` ↔ `19961200`)이고, 여러 동은 대장이 2023~2024년이다 (예 `19950522` ↔ `20230310`). 같은 필지에 새로 지은 건물을 브이월드가 아직 옛 건물로 갖고 있는 것으로 보인다.
- 주용도가 다른 15동: 제1종근린생활시설 03000 → 제2종 04000 이 7동으로 가장 많고, 단독주택 01000 → 04000 이 3동, 교육연구시설 10000 → 03000 이 2동.
- 대장의 사용승인일이 비었거나 형식이 맞지 않으면(10동) 브이월드 값을 그대로 둔다. 연면적·층수 0 도 빈 값으로 본다.

### 참고: 건물 번호로 맞추면

브이월드 `bldrgst_pk` 앞에 `11521` 을 붙이면 표제부 `mgmBldrgstPk` 와 같다 (2,013동이 맞고, 맞은 2,013동 모두 PNU 도 같음). 필지 규칙(1,163동)보다 훨씬 많은 건물을 한 동씩 맞출 수 있다. 이 방법으로 맞춘 2,013동에서 다른 값은 주용도 21, 연면적 34(±1% 밖), 지상층수 6, 사용승인일 19동이다.
다만 브이월드에서 주용도·연면적이 빈 341동 중 `bldrgst_pk` 가 있는 건물은 13동(표제부와 맞는 것 10동)뿐이라 판정불가는 거의 줄지 않는다. 이번에는 정해진 필지 규칙을 쓰고, 건물 번호 맞추기는 다음 일로 남긴다.

## 판정은 대장 값 우선

`merge_register()` 를 빈 칸만 채우던 것에서 **맞춘 건물은 표제부 값으로 바꾸는 것**으로 고쳤다.

- 표제부에 값이 있으면 브이월드 빈 칸을 채우고, 다른 값도 바꾼다. 바꾸거나 채운 속성 이름은 `props.reg` 에 남는다 (같은 값이면 남기지 않음). 화면은 `reg` 에 든 속성 옆에 "(건축물대장 표제부)" 를 붙인다.
- 브이월드 원래 값은 공개 파일(`web/data/buildings.geojson`)에 넣지 않는다.
- 결과: 빈 칸 채움 주용도·연면적·층수·사용승인일 각 11동, 다른 값 바꿈 연면적 39 · 주용도 15 · 사용승인일 18 · 지상층수 15동.
- 건물 추정 노트북(`notebooks/building_imputation.ipynb`)도 같은 규칙으로 바꿨다. 추정은 대장을 반영한 뒤에도 빈 건물에만 한다.

### 판정 규칙에 넣은 세대수 기준

판정 규칙에 `세대수: {min, max}` 를 더했다 (`collect/build_web_data.py` judge(), `web/judge.js`, 복사본 `server/lib/judge.js`. `npm test` 가 시범 27건 모두 같은 동수인지 확인).

- 건물 속성 `hhld_cnt`: 표제부를 맞춘 건물(필지에 표제부 한 줄·지도 건물 한 동)에만 표제부 세대수를 넣는다. 브이월드에는 세대수가 없다. 0 이나 빈 값은 넣지 않는다. 지금 101동에 값이 있다 (단독주택 71, 공동주택 25, 제2종근린생활시설 5).
- 판정 순서: 용도 기준이 있으면 용도를 먼저 보고(맞지 않으면 비대상), 그다음 세대수가 비었거나 0 이면 **판정불가**. 연면적·층수와 달리 용도보다 뒤에 보는 까닭은 세대수가 표제부를 맞춘 건물에만 있어서, 먼저 보면 거의 모든 건물이 판정불가가 되기 때문이다.
- 0 을 값으로 쓰지 않는 까닭: 공동주택 0 은 미기재로 보이고, 단독주택은 1,374줄이 0 이다(가구수 칸을 따로 쓰는 경우). 용도와 상관없이 0 은 "모름"으로 본다.
- 수치 비교와 경계선은 연면적·층수와 같다 (min 의 90% 이상이면 경계선, max 의 110% 이하면 경계선). 원문 대조 `check_source()` 도 세대수 수치가 근거 문구에 있는지 본다.
- 서버 에이전트의 기준 뽑기(`server/lib/criteria.js` extract·verify)도 세대수 `{min, max}` 를 받는다. 원문 대조 규칙은 연면적·층수와 같다: 근거 문구가 원문에 그대로 있고, 수치가 근거 문구에 있으며, 수치 바로 뒤에 "세대" 가 붙어 있어야 한다 (30세대, 1천 세대). "1세대 1주택", "1세대당" 처럼 이상·이하가 바로 붙지 않은 말은 뽑지 않는다. 의안 원문에서는 개정 부분 글만 보고, 같은 경계의 세대수가 여럿이면 버린다. 세대수 법안 6건(2207658, 2217163, 2213393, 2213086, 2200958, 2212443)을 배포 서버에 다시 돌리는 스크립트: `node server/scripts/household-rerun.js`.
